# 1. 系统需求设计

## 数据需求

- 用户信息：包括用户名、卡号、余额等。
- 交易记录：包括卡号、交易类型（刷卡或充值）、交易金额、交易时间等。

## 功能需求

- 刷卡功能：识别卡号，更新余额。
- 查询功能：显示用户信息，包括用户名、卡号和余额。
- 充值功能：允许用户输入充值金额，并更新余额。

# 2. 设计嵌入式数据库

## 表结构设计

- **Users** 表：存储用户信息。

  - `user_id` (INTEGER PRIMARY KEY AUTOINCREMENT)：用户ID，主键，自增。
  - `username` (TEXT)：用户名。
  - `card_number` (TEXT)：卡号，唯一。
  - `balance` (REAL)：余额。

- **Transactions** 表：存储交易记录。

  - `transaction_id` (INTEGER PRIMARY KEY AUTOINCREMENT)：交易ID，主键，自增。
  - `card_number` (TEXT)：卡号，外键。
  - `transaction_type` (TEXT)：交易类型（刷卡或充值）。
  - `amount` (REAL)：交易金额。
  - `transaction_time` (TEXT)：交易时间。

  ## 数据完整性规则

  - `Users` 表中的 `card_number` 必须是唯一的。
  - `Transactions` 表中的 `card_number` 必须在 `Users` 表中存在。
  - 余额更新时，必须检查余额是否足够，以避免透支。

  # 3. 功能模块设计

  ## 刷卡模块

  - 输入：卡号。
  - 处理：查询用户余额，减去刷卡金额。
  - 输出：更新后的余额。

  ## 查询模块

  - 输入：卡号。
  - 处理：查询用户信息和余额。
  - 输出：显示用户信息和余额。

  ## 充值模块

  - 输入：卡号、充值金额。
  - 处理：更新用户余额。
  - 输出：更新后的余额。

  # 4. 界面设计

  ## 主界面

  - 显示三个主要功能按钮：刷卡、查询、充值。

  ## 刷卡界面

  - 输入框：输入卡号。
  - 刷卡按钮：提交刷卡请求。
  - 显示区域：显示刷卡结果和更新后的余额。

  ## 查询界面

  - 输入框：输入卡号。
  - 查询按钮：提交查询请求。
  - 显示区域：显示用户信息和余额。

  ## 充值界面

  - 输入框：输入卡号和充值金额。
  - 充值按钮：提交充值请求。
  - 显示区域：显示充值结果和更新后的余额。
